How a line of FireRed becomes a flashcard

The deck has 11,251 cards. Each one is a word, in one form, in the sentence where the Japanese game first uses it. This page follows the text from the cartridge's script to the card.

Why a dictionary is not enough

FireRed's Japanese script is written almost entirely in kana. In 358,000 characters of text there is one kanji, 円. That is kind to a child reading the game and hard on a program reading it, for two reasons.

The same kana is several words. かみ is paper (紙), a god (神) or hair (髪). Only the sentence says which.

The spaces are not word boundaries. The game puts a full-width space between phrases, so a noun arrives glued to its particle and a verb to its endings. A standard tokenizer, trained on text with kanji, has to guess where the words are, and it guesses wrong often. It reads てんそう (転送, transfer) as three scraps: て + ん + そう.

So every sentence is read by a language model that can see the sentences around it, who is speaking and where in the game it is. The tokenizer and the dictionary still run first, but as a list of suggestions the model picks from, and as a check on what it answers.

The pipeline

Seven stages, each a Python module that reads the previous stage's file and writes its own. Yellow stages call Claude. Everything they answer is cached on disk, so a rebuild makes no calls.

Extract: from script dump to sentences

The source is poke-corpus, which holds the FireRed and LeafGreen script as parallel files: one with message IDs, one per language, line for line. Each ID carries the same label the decompiled game uses, which is what later ties a line to a map.

frlg.script.ViridianForest.ViridianForest_Text_RickIntro
よーしッ！\nきみは　ポケモン　もってるな？\rしょうぶ　しようぜ！

Of 14,480 lines, 12,895 have text. The stage then:

  • Keeps FireRed. LeafGreen's Pokédex text and its versions of the in-game trades are dropped.
  • Fills in names. [PLAYER] becomes レッド and [RIVAL] グリーン, the game's own default names. Names and numbers the game fills in at runtime become ＊, which no later stage treats as a word.
  • Removes control codes. About ninety kinds: colours, pauses, music cues, fonts. A code it does not recognise stops the run instead of slipping through.
  • Finds the speaker. オーキド『… names who is talking; the name goes to its own column.
  • Splits into sentences at 。！？. A page of the text box that does not end a sentence runs on into the next page, unless a new speaker starts there.

The result is 16,166 sentences, 13,661 of them distinct. Each keeps its message ID, speaker and the raw line.

Order: when do you first see each line?

The script is filed by map, not by story. Ordering it is the largest part of the project, and it works differently for dialogue and for everything else.

Dialogue follows the walkthrough

map_order.yaml lists 344 maps and scenes in play order: Kanto, the first three Sevii Islands after Blaine, the League, then the postgame. It was drafted from the decomp's map names and checked against all 21 parts of Bulbapedia's walkthrough.

Two details matter. A map you return to can list single messages to be placed later, so the rival's second battle on Route 22 sits after the eighth badge and not at your first visit. And the game's opening is listed message by message, because the script dump stores it out of order: controls guide, intro pages, Professor Oak's speech, then the naming prompts.

Everything else goes where it first appears

Menus, battle messages, move and item descriptions and Pokédex entries have no map. Most of them can be worked out from the decompiled game:

"Never met" is mostly Ruby and Sapphire data still in the cartridge: Hoenn species, items and trainers a FireRed player cannot reach. That text is left out of the deck, and no model stage ever sees it. So is text the decomp marks as unused: 35 messages no script calls, such as the Trainer School e-mail from the Ruby and Sapphire rival's computer, which a model had placed at the PC in your room.

A third kind was found late: text the English game left in Japanese. The translators skipped what no script shows, and the decomp says so at the top of the Safari Zone's text ("a copy/paste from Hoenn's Safari Zone, and any unused text was left untranslated"). So a line whose English copy is still Japanese is a leftover. There were 151 such messages in the story part of the deck, 230 sentences that 232 cards had been built on: Hoenn's Safari Zone with its ポロック, berry tags, the rival's lines for battles you cannot lose and carry on. None is called by any script in the decomp. The same test marks 113 sentences at the end of the deck (link play, the union room); those stay, because an English decomp cannot say what the Japanese release's own features, such as the e-Reader, showed.

Together that is 1,271 messages, listed with the reason in data/never_shown.csv.

Battle messages needed the most care. The game's battle scripts say which move effect prints which message, so each effect's script is followed through its jumps, shared sub-scripts and message tables. "＊は　へんしんした" then sits on Route 13, where Ditto appears, instead of in your first battle. Three corrections came out of checking the results: surfing and fishing encounters count only once you have Surf or a rod; a trainer counts from where their battle text is placed; and the engine's own table pads unused effects with the sleep script, which has to be ignored.

Rules for the rest, and a model for what no rule fits

What the decomp cannot say is handled by first_seen.yaml: rules per group of text, matching on the programmers' labels. PC screens go to the first Pokémon Center, badge names to their gym, each quest-log line to the place or action it recaps, the Help menu and error messages to the end.

Some groups are too mixed for keywords. For those, the classify stage shows Claude each string's label, Japanese and English text and asks it to pick one of 56 story points. It placed 835 strings this way; the answers are saved in first_seen_llm.yaml where you can read and correct them.

Spreading, so menus never come in a block

Placing every line exactly where it is first seen put about 2,700 cards of menu and battle text before the story reached the second house. So the game is cut into ten chapters, one per gym badge, then the League, then the postgame. Inside a chapter:

  1. A non-dialogue line is kept only if it teaches something that neither earlier chapters nor this chapter's dialogue teach. Most do not, and are held back as extra example sentences.
  2. The kept lines are spread evenly through the chapter's dialogue, each one no earlier than the point where it is first seen.
  3. At each slot the line with the most common new words per word of text goes first, so short menu words come before long help-style prose.
  4. If dialogue in the same chapter uses the same word, the dialogue sentence becomes the card's example.

One kind of line is not spread: the line that names a Pokémon, an item, a move, an ability or a place. It stays where the thing is first met, unless dialogue has already said the name by then, and the order stage works out where inside the map that is:

  • A trainer's Pokémon goes right after that trainer's challenge, followed by the moves it shows and its ability. Brock's gym reads: his challenge, イシツブテ, まるくなる, がんじょう, いしあたま, イワーク, しめつける, がんせきふうじ, his defeat line. Where a trainer has no challenge line (the rival in Oak's lab), the team goes right before the defeat line. On the same map a trainer's Pokémon wins over a wild one, because its place is exact.
  • Wild and gift Pokémon have no line to hang on. A map's sightings are spread evenly between its messages, each Pokémon still followed by its moves and ability.
  • A move belongs to the first Pokémon that knows it at the level you meet it, or to its TM. An ability belongs to the first Pokémon that has it, and a type to the first Pokémon of that type: みず "Water (Pokémon type)" comes with the rival's ゼニガメ.
  • A place comes before its map's dialogue: its name comes up as you walk in.
  • An item comes after the dialogue of the map where it can first be had.

This runs twice: here on tokenizer guesses, as a preview, and again in the cards stage on the model's real word senses.

Tokenize: suggestions for the model

fugashi with UniDic splits each of the 11,163 distinct sentences and gives a dictionary form and part of speech per piece. Then every entry JMdict has for those pieces is collected, 13,171 entries in all, a median of 16 per sentence.

Because the split is often wrong, single pieces are not enough. Within each space-separated phrase, runs of up to four adjacent pieces are looked up too, as written and with the last piece in dictionary form. That is how てんそう still offers 転送 after being split in three. Words never cross the game's spaces, so runs do not either.

Analyse: one model call per forty sentences

Sentences are sent in batches of up to 40, in game order, cut only between messages so a conversation is never split. Each sentence comes with its map, its speaker, the tokenizer's split and the candidate dictionary entries. The model returns, for every sentence, a version in normal kanji, an English translation, and every word with:

  • the form as written and its dictionary form;
  • the kanji spelling, whether it is usually written in kana, and each character's reading;
  • a literal meaning and the meaning in this sentence;
  • how the form is built, ending by ending;
  • the JMdict entry and sense that fit, or nothing if none does;
  • whether it is a name, and whether the model is unsure.

Names are not left to the model. It called ピーピーエイダー a Max Ether (it is the Elixir), イノムー Swinub (Piloswine), チャンピオンロード "Champion Road" (Victory Road). So each batch carries the English names of the Pokémon, items, moves, abilities, places, people and badges its sentences mention, 1,302 in all. Most are taken from the same lines of the English game; a town's short name follows from its full one (ニビ is Pewter because ニビシティ is Pewter City). People and badges have no list in the game, so they are kept by hand in names_by_hand.yaml, 91 names with places, game terms and real-world names, each checked against the English script line that pairs with a Japanese line saying it: マサキ is Bill, グレーバッジ the Boulder Badge. The player and the rival are left as Red and Green, the names the deck fills in for them. A batch of forty gets about five. They are offered, not imposed: the letters of a name are often an ordinary word (じしん is Earthquake and also "confidence"), and the model is told so. Twelve-letter squeezes are replaced by today's spelling from a hand-kept list of 37 (name_spellings.yaml: PARLYZ HEAL is Paralyze Heal, SELFDESTRUCT Self-Destruct). The grammar pass gets the same list.

A check then looks at every sentence where the analysis found a name and has the sentence redone if its translation calls the thing something else. An answer given with the names in the prompt is left alone, so a sentence where the model had a reason is not asked about for ever. On the whole deck that was 91 sentences, nine calls, and six grammar answers. A line of a name list needs no model at all: its translation is the name.

The calls go through headless Claude Code (claude -p) with tools switched off, the project's own system prompt and a JSON schema the CLI enforces, so a malformed answer fails instead of being stored. Results are cached by sentence text. A sentence is never sent twice, and a run that hits a usage limit waits and resumes.

More effort did not help and larger batches did not hurt, so the full run used Sonnet at low effort in batches of 40: 322 calls for the first pass.

A second opinion where it is needed

A sentence is sent again, to Opus, when one of its words is marked unsure, has a form that does not match the entry chosen for it, or points at an entry or sense that does not exist. Names are exempt. That was 2,132 sentences, about one in six. Afterwards 0.7% of words are still marked unsure, down from 3.1%.

Particles: one card for each job

Short grammar words do several jobs each. か asks a question or means "or"; が marks the subject or means "but". The analysis mostly leaves them without a dictionary sense, and grounding does not look them up, because one spelling has many entries. So every use of a particle used to land on one card, which showed whatever its first sentence said. か "or" was taught on two cards, and か the question marker on none.

The analysis is now shown those entries: for every short kana word, and for runs of them, the JMdict entries written in kana with that reading, with all their senses. It picks the sense with the rest of the word's analysis. A few lines in its instructions keep the word boundaries in place. Decide the words first and only then look them up. Never cut inside a conjugated form: はけば is one word, because はけ cannot stand alone. And for a run of particles, keep it whole only when the dictionary has an entry for it and one of its pieces has no sense of its own that fits: かな "I wonder" is one word, and so are のだ, んだ and のか, because the dictionary's の has no sense for explaining. Where every piece does a job it has a sense for, they are separate words: には is に + は. A phrase whose meaning is just its words together is never one word, even when the dictionary lists it (においがする); a set expression that means more than its words stays whole (というわけだ, "so that's how it is").

That wording took four rounds. Offered the particle entries with no rule, the model cut ば off verbs in one sentence in five. Told that "a compound the dictionary lists stays one word", it joined には, にも and whole phrases such as においがする. Kept apart, the の of のだ had nowhere to go: of 52 uses, 36 were filed under "turns a verb into a noun". And told that "a phrase is never one word", it took というわけだ apart into four words.

Each sense then gets its own card at the first sentence that has it: に has cards for "at", "to", "for (a purpose)", "as" and "from (someone)". A separate pass (particles) asks about the uses the analysis leaves without a sense, showing the sentence with the word marked. Where no listed sense fits, as with と naming what something becomes in しゅじんこうと　なって, the use keeps a card of its own and is not filed under another sense.

In the first chapter the analysis gave a sense to 2,823 of 2,848 particle words, and the extra pass was two small calls. In the later chapters a particle's uses are still filed under one card; shown as an extra example on a first-chapter card, such a use comes after the ones that were checked.

One decision per string

A rule in prose only goes so far. The analysis decides where words begin and end one sentence at a time and cannot see what it chose elsewhere, so the same string came out as one word in some sentences and as several in others: ポケモンセンター twice whole and five times in two pieces, ように three times whole and seven times cut. In the first chapter that was 67 strings, and every rerun cut a fifth of the chapter differently.

The splits stage settles each string once. It finds the strings cut two ways and asks Claude about each, twice and independently, showing the sentences, the glosses and the dictionary entries: always one word, always the same pieces, or "it depends on the meaning" (でも is "but" as one word and で + も as two). A string is fixed only where the two answers agree; otherwise it is left to the rule. The decisions go to splits.yaml with their reasons, the analysis is shown the ones that apply to its batch, and a check in code re-analyses the sentences that break one.

The first chapter needed 72 decisions: 29 strings fixed as one word, 23 fixed as cut, 20 left to the rule. 89 sentences were re-analysed. Afterwards 17 strings are still cut two ways, all of them ones where the meaning decides.

Opus for whole chapters

The second opinion only reaches sentences where Sonnet shows doubt. It cannot catch a confident mistake. The line for the SELECT button, たいせつな　ものを　とうろくして　つかいます, came back as "to register important things"; Opus reads it as the game means it, "to use a registered Key Item".

To see how often that happens, Opus analysed 100 sentences that only Sonnet had seen, taken from ten points in the game. It fixed a clear error in 3: an item name (かいふくのくすり is Full Restore, not Potion), ひとつ　たのまれて！ ("do me a favor", not "I was asked a favor"), and あったら filed under ある where it is 合う. About six more were real improvements, one was slightly worse, and the rest differed only in wording.

On that evidence the first chapter was redone on Opus: first the 993 sentences only Sonnet had seen, later the whole chapter again with the prompt that also covers particles, about 1,200 sentences in 31 calls, twenty at a time, in 10 minutes. Opus also splits words more strictly, with particles and する apart from what they follow, in about one sentence in five, so 127 of the chapter's 2,518 cards went and 95 new ones appeared. The other nine chapters are still Sonnet's.

Batches stay at 40 sentences for either model. On the same 80 sentences, batches of 10 and 40 gave the same result, and a single batch of 80 dropped answers in its last third.

Grounding

When the tokenizer misreads a word, the right entry may not be among the candidates, and the model answers correctly but without an ID: it says とおり is 通る while the candidates only offered the noun 通り. After the pass, the model's own kanji and dictionary form are looked up in JMdict, and the entry is filled in when exactly one matches. Short grammar words such as の and が are not looked up this way, because several entries share each spelling.

An ID the model gives is checked too, against the whole dictionary. Three things came out of checking Opus's answers by hand. It links particles to their real entries, which are never among the candidates. Its entry is sometimes a neighbour of the right one (んだ tied to なのだ, おぼえさせる to 覚める): when the entry lists neither the word's forms nor the form in the sentence and exactly one other entry does, that one is taken. And it cites senses past the five the model is shown, from memory, sometimes one off: eight 〜てあげる cards pointed at あげる sense 23, "to vomit", where sense 24 is "to do for". Such a sense is moved only when another one shares two or more words with the model's own gloss.

A lookup by reading can go wrong in two ways, so a small extra pass (sense_pick) shows Claude each of the 1,511 words linked this way, with its sentence and the gloss already written for it. First, the entry may be a different word that only sounds the same: ＰＰ, read ピーピー, had matched "peep; chirp", and ばいばい had matched 売買 "trade". Those links are removed, 24 in all, but only when the word's kanji is not the entry's own. Second, the lookup cannot say which sense is meant: 教えてください now gets 下さる "to kindly do for one", not "to give".

Grammar: what sits between words

The word analysis explains each word alone. It cannot say that the と in しゅじんこうと　なって belongs to なる, or that することに　なります is one pattern. A second pass reads each sentence again, with its translation and word list, and returns two things:

  • A breakdown: the sentence cut into phrases, each with a short English gloss.
  • Up to three patterns: a name (〜ことになる, 〜で (how), verb + noun), the stretch of the sentence that shows it, the words that take part, and one or two sentences of explanation ending in what that stretch means.

A word's card shows the patterns that word takes part in, and the breakdown sits behind a fold. There are no cards for the patterns themselves.

The explanations are asked for in plain words. The first version said "で marks the manner/basis", which told a learner nothing; it now says "で after a word tells you the way something is done". Three terms survive because nothing shorter exists: て-form, plain verb, verb stem.

Everything on a card was written for that card's sentence. An index of patterns was tried and removed: it gave each pattern name one fixed heading, and a name that covers several uses then put a line on the card that contradicted the explanation under it (から "because" headed "the starting point: from"). The price is that one pattern can be spelled two ways on different cards.

The pass runs on Opus, like the analysis it builds on. It first ran on Sonnet, which is given the translation but, where it would have read the sentence differently, glossed a phrase its own way: under the translation "using a registered Key Item", the breakdown of とうろくして　つかいます said "registering important things / it is used". Opus writes "registering a Key Item and / using it". In 30 breakdowns drawn at random after the change, all agree with their translations.

Answers are cached by sentence and word list, so a sentence the analysis later splits differently is asked again, and so is one answered by another model. The first chapter is 1,167 sentences, not counting 56 lines that are only a name and are skipped: 31 calls, eight at a time, five minutes. 789 of them have at least one pattern, 1,511 patterns in all.

Cards: one per form, in order

Every analysed word is an occurrence with a key: the dictionary entry, the sense, and the form as written. つかまえた, つかまえて and つかまえられる have three keys and become three cards. That is deliberate: each form is drilled where the story first uses it. する alone has 194.

  • Names have one card each in the main deck: Pokémon, items, moves, abilities, places, the main characters, badges and a few game terms. The analysis reads a name as its words (げんき + の + かけら), which is right for the words and leaves the Revive itself without a card. So the names are found afterwards: a word the analysis marked as that name, or a run of words that spells it. The card sits at the first dialogue line that says the name, or else at the name's own line in the game's list, where the thing is first met. It gives the name the English game uses and the parts as the literal meaning. A word that only looks like a name is left alone: クラブ "club" is not Krabby, かたく　なる "become hard" is not Harden. A thing called by an ordinary word that nothing uses as a name (じてんしゃ, bicycle) keeps that word's card.
  • Any other name makes no card: the presets of the naming screen, a character who appears once, a piece of a longer name. There used to be a second deck for these; it had nothing left worth learning. A cry or a shouted name (ぴかちゅ, やどらーん) keeps its card, because the card is what explains it. Trainer names are not carded at all.
  • Notes. A name can carry a short note where it takes knowledge a learner may not have: something from Japan (ファミコン is the Family Computer, sold abroad as the NES; はないちもんめ is a children's game), or from another Pokémon game (オダマキ is Professor Birch of Hoenn). The notes are written by hand in names_by_hand.yaml, and say so where the English game replaced the reference (Tokyo Tower became Ayers Rock).
  • Known words listed in known.txt are skipped.
  • Sense merge. JMdict splits meanings finely, and the model sometimes picks neighbouring senses for the same idea. Each of the 588 entries used in more than one sense goes to Claude once, with its sentences, to group senses a learner would treat as one. 戦う and 出る were merged; 見る "to see" and 〜てみる "to try" were kept apart.
  • Order. The chapter spreading runs again on these real keys.
  • Example. A card takes the first sentence in that order, with the dialogue preference above. Up to two later sentences are kept as extra examples, each with its own form explained.
  • Dictionary sense. The back shows the JMdict definition of the sense chosen for that sentence. Two cards for あぶない can both be glossed "dangerous"; this line says one is "dangerous; risky" and the other "close (call); narrow (escape)".
  • Grammar. Where the grammar pass has covered the sentence, the card gets the patterns its word takes part in and the sentence's breakdown.
  • Romaji is converted from the kana by table, with spaces between words and particles written as read: は as wa, を as o.

Before writing the result, the stage prints 30 random cards as plain text for checking by eye.

Build: packages that can be rebuilt

genanki writes one package. The note type and deck have fixed IDs, and each note's ID is derived from its key. Importing a rebuilt deck therefore updates the cards you already have and leaves their review history alone.

Notes are added in story order. In Anki, set the deck's new-card order to "order added". When re-importing after a template change, set "Update note types" to "Always", or Anki keeps the old template. New fields go at the end of the note type (two for the grammar in v1.2, one for notes on names since), so an import over an older deck also needs "Merge note types".

The first chapter is the largest because the menus, the battle screen and most everyday vocabulary all appear before the first gym. The deck's first 168 cards are the opening sequence alone.

  • 6,343 distinct dictionary forms across the 11,251 cards.
  • 6,912 cards take their example from story dialogue; the rest from Pokédex entries, menus, move and item descriptions and battle messages.
  • 110 cards are tagged low-confidence: the dictionary entry does not match the word, there is no entry and the model was unsure, or the word is a scrap of broken text. A doubt only about which listed sense fits a helper verb or an idiom no longer counts; those glosses were checked by hand. 10 are tagged sense-guessed.
  • 2,454 of the first chapter's 2,510 cards carry a sentence breakdown, and 1,186 of them a grammar pattern for their word. The other 56 are names on their own line, with no sentence to break down.
  • 210 are tagged onomatopoeia: JMdict marks the sense as a sound or mimetic word (ドキドキ, キラキラ), and the back says so.
  • 67 are tagged fragment: stammers, garbled speech and pieces of interrupted words (こっ　こんなに). They stay in the deck because the card is what explains them.

The first full analysis took about five hours of calls including one usage-limit pause. A classify pass is about 21 calls. Redoing the first chapter on Opus took 10 minutes, and its grammar pass 5.

A rule change that brings in text not seen before needs tokenize and analyse full as well; they only work on what is missing from the cache. Changing the analysis prompt does not re-run cached sentences by itself: delete the cache entries you want redone.

Hand corrections are kept apart from the model's answers. The cache stays raw, and corrections.yaml is laid over it each time it is read, so running the model again never loses a correction. Each one names what it corrects: a word by its form, a breakdown line by its Japanese, a pattern by its span. If a rerun changes the answer so that a correction no longer fits, the cards stage stops and names it.

Known limits

  • The deck is in two states: the first chapter is Opus's analysis with grammar on its cards; the other nine are Sonnet's, with Opus only where Sonnet showed doubt, and have no grammar yet.
  • Particles are split into one card per job only in the first chapter; in the later chapters all uses of a particle are still filed under one card.
  • A grammar pattern is named per sentence, so one pattern can be spelled two ways on different cards (〜せる and 〜させる). The explanations have not been checked one by one.
  • About 250 battle messages and 580 other strings are placed by the model's judgement. Ability messages and trainer-battle text are among them.
  • Rematch lines of ordinary trainers sit at their route's first visit, though you only see them with the VS Seeker.
  • All 25 nature names are placed together at Professor Oak's lab.
  • A wild Pokémon is spread along its route by rule, not by where its grass is, and a move is placed with the first Pokémon that could show it, whether or not it uses it.
  • A map's dialogue is all placed at the map's first visit, so a name first said on a later visit (１のしま in Oak's lab) gets its card early.
  • A Pokémon or an item is placed with the map where it is first met or found, at that map's first visit, even where it is in a part of the map reached only later.
  • The dictionary is the 2020 JMdict snapshot shipped with jamdict.
  • The order follows one walkthrough. The game lets you do several stretches in a different order.
